# S011 — error-path input preservation (candidate-009 proposal)

Declared November 5, 2026, before building candidate-009. This is CPU-only work, with no model generation and no training. Final/regression tasks are never read.

## Purpose

This closes independent-audit finding N7. In 19 list-input tasks, mutating an input before raising the expected exception goes undetected. The contract already says "Do not mutate any input or nested mutable elements", but the model-visible coverage expectations ask only for before/after checks on valid calls.

## Change (one variable)

The change applies only to the 19 tasks whose coverage expectations contain "Compare valid inputs before and after calls.":

1. **Model-visible instruction.** That sentence becomes "Compare inputs before and after every call, including calls that raise." No other wording changes.
2. **Gold.** Every `test_raises_*` function takes a `copy.deepcopy` of `args` before the call and asserts `args == before` after the expected exception.
3. **Training answer.** The code block is the new gold. "Valid-input preservation is checked before/after calls." becomes "Input preservation is checked before/after every call, including expected-exception calls."
4. **Mutants.**
   - All candidate-008 mutants are kept, with the same ids and sources.
   - The audit's `mutation-error` mutants are regenerated by the audit code and hash-checked.
   - Each is promoted with a declared witness: an invalid case where the expected exception is raised but an argument changed.

References, cases and oracle files are unchanged. The other 53 tasks are byte-identical to candidate-008.

## Gates

- All gold suites pass the unchanged references.
- Every designated mutant fails at its declared witness node.
- The audit rerun from 008 to 009 reports no new gaps.
- The token profile is measured with the pinned tokenizer, through the cloud workflow.

## Approval required

Approval of candidate-008 does not transfer, because this changes model-visible instructions. Candidate-009 needs explicit user approval of the new sentence and of its `SHA256.json` hash before any use.
